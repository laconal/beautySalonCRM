# Документация по исключениям (Exceptions)

Этот документ описывает все бизнес-исключения бэкенда (`src/exceptions/`) для команды фронтенда. Каждое исключение сериализуется в ответ API с полями:

- `errorCode` — уникальный код ошибки (строка), по которому фронтенд может определить тип ошибки и показать нужное сообщение/поведение;
- `statusCode` — HTTP статус-код ответа;
- `detail` — человекочитаемое описание ошибки (на английском, для логов/дебага, не для показа пользователю "как есть");
- дополнительные метаданные (например, `id`, `name`, `firstname` и т.д.) — контекст ошибки, может использоваться для подстановки в локализованные сообщения на фронте.

Общий базовый класс: `BaseAppException` (`src/exceptions/base.py`) — от него наследуются все остальные исключения. Значения по умолчанию: `statusCode = 500`, `errorCode = "INTERNAL_ERROR"`.

## Auth (аутентификация и авторизация)

Файл: `src/exceptions/auth_exceptions.py`

| errorCode                      | statusCode | Смысл / когда возникает                                                                                                                  |
| ------------------------------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTH_OR_TENANT_CONTEXT_EMPTY` | 404        | В запросе отсутствует контекст авторизации или организации (tenant) — например, не передан/не распознан токен или заголовок организации. |
| `INCORRECT_CREDENTIALS`        | 401        | Неверный логин или пароль при входе в систему.                                                                                           |
| `TOO_MANY_LOGIN_ATTEMPTS`      | 429        | С данного IP-адреса зафиксировано слишком много неудачных попыток входа (10 за 10 минут) — IP заблокирован для входа на 30 минут. В метаданных передаётся `blocked_until` (ISO-время окончания блокировки). |
| `ACCOUNT_TEMPORARILY_LOCKED`   | 429        | Для данного логина зафиксировано слишком много неудачных попыток входа (10 за 10 минут, в том числе с разных IP) — учётная запись временно заблокирована на 30 минут. В метаданных передаётся `blocked_until`. |
| `INCORRECT_OLD_PASSWORD`       | 401        | При смене пароля указан неверный текущий (старый) пароль.                                                                                |
| `TENANT_IS_INACTIVE`           | 403        | Организация (салон/арендатор), к которой относится пользователь, деактивирована — доступ запрещён.                                       |
| `REFRESH_TOKEN_MISSING`        | 401        | Не передан refresh-токен при попытке обновить сессию.                                                                                    |
| `INVALID_TOKEN`                | 401        | Токен (access или refresh) недействителен: истёк, повреждён или подделан.                                                                |
| `ADMIN_PREVILIGES_REQUIRED`    | 403        | Действие доступно только пользователям с типом "администратор".                                                                          |
| `NOT_ENOUGH_PERMISSIONS`       | 403        | У пользователя недостаточно прав для выполнения действия. В метаданных передаётся `required_permissions` — какие права требовались.      |
| `PERMISSION_NOT_FOUND`         | 404        | Указанное разрешение (permission) с кодом `code` не найдено в системе.                                                                   |

## Staff (персонал / доступ сотрудников)

Файл: `src/exceptions/staff_exceptions.py`

Staff — учётная запись сотрудника с доступом в систему (в отличие от Employee — исполнителя услуг).

| errorCode               | statusCode | Смысл / когда возникает                                                                                                             |
| ----------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `STAFF_IS_INACTIVE`     | 409        | Учётная запись сотрудника деактивирована.                                                                                           |
| `STAFF_NOT_FOUND`       | 404        | Учётная запись сотрудника не найдена.                                                                                               |
| `STAFF_TENANT_CONFLICT` | 409        | Учётная запись сотрудника (`staffID`) не принадлежит указанной организации (`tenantID`) — например, при управлении админом филиала. |
| `STAFF_LOGIN_DUPLICATE` | 409        | Указанный логин (`login`) уже используется другой учётной записью — логин уникален глобально, не в рамках одной организации.        |

## Как фронтенду работать с этими ошибками

1. Всегда ориентируйтесь на `errorCode`, а не на `detail` — `detail` может меняться и не предназначен для показа пользователю "как есть" (это англоязычный технический текст для отладки).
2. `statusCode` в ответе API совпадает с HTTP-статусом ответа — можно использовать для базовой обработки (404 → "не найдено", 409 → конфликт состояния, 400 → ошибка валидации, 401/403 → проблемы авторизации).
3. Дополнительные метаданные (например `id`, `name`, `firstname`, `required`, `has` и т.д.) можно использовать для подстановки значений в локализованные (русские) сообщения на фронтенде, не полагаясь на английский `detail`.
